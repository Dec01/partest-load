# Решение: авторизация, контракт и редактирование секретов берутся из partest

## Контекст

Пакет переносится из самостоятельного прототипа (`github.com/Dec01/load`), у которого были
своя авторизация, свой разбор спецификации и своя работа с заголовками. Нужно было решить,
что из этого остаётся при переезде в семейство.

## Решение

Не остаётся ничего из перечисленного. Зависимость `partest>=1.8` объявлена в
`pyproject.toml`, и через неё берётся:

| Задача | Откуда |
|---|---|
| Авторизация, мульти-ролевые токены | `partest.TokenManager` |
| Заголовки, параметры, привязка токена | `partest.http.Config`, `HeadersBind` |
| Список эндпоинтов и шаблоны путей | `partest.openapi`, `partest.path_match` |
| Редактирование секретов | `partest.redact` |
| Маркировка созданных данных | `partest.data_marker` |

**Своей авторизации, своего разбора спецификации и своего редактирования секретов здесь
быть не должно.**

## Почему

Три причины, и третья важнее первых двух.

1. Дубль расходится. Две реализации разбора спецификации живут одинаково ровно до первого
   нестандартного контракта, после чего нагрузочный прогон и функциональный видят разные
   списки эндпоинтов — и никто этого не замечает, потому что оба «работают».
2. Редактирование секретов должно быть одно. Проверять на утечки два разных механизма
   вдвое дороже, а доверять непроверенному нельзя вовсе.
3. Профиль пишется **на контракт**, а не на список URL. Это следствие, а не совпадение:
   раз эндпоинты берутся из спецификации, изменение спецификации немедленно видно профилю.
   Руками перечисленный список молчит и продолжает нагружать то, чего уже нет.

## Последствия

- `partest` становится обязательной зависимостью, а не удобством. Нагрузочный прогон без
  неё невозможен.
- Направление строго одностороннее: `partest` про `partest-load` не знает. Возможность,
  полезная проекту вне нагрузки, реализуется в `partest`, а не здесь.
- Обновление `partest` требует проверки совместимости здесь: список эндпоинтов, работа
  с токенами и редактирование секретов приходят оттуда.
