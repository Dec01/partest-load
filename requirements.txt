# Цель этого файла — аудит зависимостей, а не установка.
#
# Устанавливается пакет через `pip install partest-load` (или `-e .`), и состав
# зависимостей объявлен в `setup.py`. Но `pip-audit` читает зависимости только из
# `pyproject.toml` или из `requirements.txt`: объявленные императивно в `setup.py`
# он статически не видит и честно отвечает «не проверено».
#
# Пока файла не было, ворота писали «pip-audit НЕ ПРОВЕРЕНО», и это неотличимо
# от «уязвимостей нет» ровно настолько, насколько читатель невнимателен. Тот же
# приём у partest — там `requirements.txt` лежит по той же причине.
#
# Здесь перечислено всё, что пакет тянет в прогоне: обязательное из
# `install_requires` и необязательное из extra `report`. Расхождение с `setup.py`
# ловится тестом упаковки — **по именам и по границам**: список, где имена те же, а
# пол ниже, аудиту врёт ровно так же, как список с пропущенным именем.
#
# Осторожно с тем, что именно проверяет `pip-audit -r`: по файлу с `>=` он разрешает
# зависимости в новейшее и проверяет ИХ. На вопрос «что будет у потребителя, который
# встал на объявленный пол» он так не отвечает. Для этого границы приводятся к
# `имя==пол` и скармливаются с `--no-deps`.

# --- обязательные, install_requires ---
