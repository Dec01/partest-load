# partest-load

Нагрузочный харнесс семейства **partest**: профили нагрузки по времени, метрики насыщения и
деградации, HTML-дашборд.

**PyPI:** `partest-load` · **Лицензия:** MIT

```bash
pip install partest-load
```

## Что делает

Нагрузка задаётся **временем, а не количеством запросов** — это принципиально: интересует
не «сколько мы отправили», а «где система перестала держать».

| Профиль | Что делает | Что показывает |
|---|---|---|
| `linear` | постоянная нагрузка | держит ли систему на заданном уровне |
| `ramp` | плавный рост до плато и спад | где начинается деградация |
| `stress` | агрессивный рост до отказа | точка насыщения и наклон деградации |

Метрики: RPS, перцентили задержки, доля успехов и ошибок, размеры ответов; для `stress` —
точка насыщения и наклон деградации.

## Отношение к partest

Пакет **не изобретает то, что уже есть в семействе**:

| Задача | Откуда берётся |
|---|---|
| Авторизация, мульти-ролевые токены | `partest.TokenManager` |
| Заголовки, параметры, привязка токена | `partest.http.Config`, `HeadersBind` |
| Список эндпоинтов и шаблоны путей | `partest.openapi`, `partest.path_match` |
| Редактирование секретов в отчёте | `partest.redact` |

Отсюда следствие: профиль пишется **на контракт**, а не на руками перечисленные URL. Список
эндпоинтов берётся из спецификации, и при её изменении профиль не разъезжается молча.

## Отношение к карте «Веха»

Помимо своего дашборда пакет пишет артефакт `atlas/<система>/<контур>/load.json`
(`kind: load.profile`) — на эндпоинт: достигнутый RPS, перцентили, доля ошибок, точка
насыщения, наклон деградации.

Сам по себе это ещё один отчёт. Смысл появляется при наложении на граф связей: нагрузочный
инструмент в одиночку говорит «эндпоинт X деградирует на 200 RPS», карта говорит «X, Y и Z
деградируют вместе, и за всеми тремя стоит одна таблица». Артефакт пишется всегда и никого
ни к чему не обязывает — потребителя может и не быть.

## Устройство

```text
partest_load/
  configs/     описания эндпоинтов и профилей (в пакете — только схемы, не значения)
  core/        клиент, метрики, воркер, раннер
  engines/     реализации профилей: linear, ramp, stress
  storage/     сохранение результатов и схемы данных
  reporting/   HTML-дашборд (Jinja2 + Plotly)
  artifacts.py выгрузка `load.profile`
```

## Быстрый старт

```bash
partest-load --endpoint orders_create --profile ramp
# отчёт: reports/dashboard.html
```

## Статус

Ранняя разработка. Код переносится из прототипа `github.com/Dec01/load` со снятием
проектного домена: конкретные эндпоинты, адреса стендов и учётные данные уходят в примеры и
в конфигурацию потребителя, в пакете остаются схемы и движки.
